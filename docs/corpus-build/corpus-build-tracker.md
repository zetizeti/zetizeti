## The goal, and what "done" means

Build **Part B (domain corpus)** — synthetic, copyright-clean design tensions, each two-sided and
anchored to verified citations — broad enough to meet a design student wherever they reach, and
**Part A (method corpus)** — the questioning method — with enough depth to match Part B.

An entry is **DONE only when it reads `verified`** — which, mechanically, means its
`**provenance:** pending` line has been *deleted* (retrieval defaults absent provenance to
`verified`; the curtain then shows `✓` not `◔`). **Only Prayas's human sign-off deletes that line.**
Clearing the analytical passes and the live citation pass is necessary but **not** sufficient
(architecture.md §3a: the passes are a filter; the real floor is the citation layer + human
sign-off + a spot-check). Verification sets the pace, not breadth (invariant #0).

---

## The pipeline (every entry's journey)

```
  draft (synthetic prose, two-sided)
    → Pass 1  factual/citation grounding + copyright gate   (academic-analyst, adversarial)
    → Pass 2  logical parsing (de-gotcha, flip-test, redundancy)
    → Pass 3  philosophical / SDC parsing (no smuggled verdict, argued counter)
    → Pass 4  LIVE external citation verification (citation-verifier, Crossref/publisher — MANDATORY)
    → [Consensus framing check, for empirical claims — original papers, never proxy links]
    → GATE 4: Prayas's human sign-off  ← the only step that flips pending → verified
```
Independent invocation per pass, fresh context, "find what's wrong". **Not self-review in the
authoring context.** Any regeneration of an entry voids its tag and re-runs the passes.

## Method reference (how an entry is built, for resuming)

1. **Pick genuine, distinct, two-sided tensions** for the domain — anchored to real named thinkers/works.
   Don't pad to a number.
2. **Verify citations FIRST** (before drafting prose): Perplexity / Crossref / publisher — author,
   title, venue, year. Never cite from memory.
3. **Consensus-check empirical/contested claims** (sequential, one call at a time — never parallel);
   confirm the literature holds the tension **two-sided**; cite original papers.
   Positions-held-in-named-works (not contested empirical claims) are citation-verified only, like
   `first-things-first` — no dedicated Consensus pass.
4. **Draft** in the file's register: `## entry: slug` + `**discipline:**` `**vocabulary:**`
   `**felt as:**` `**the_tension:**` (two paragraphs, the second with the attributed counter in
   parens) `**questions_it_invites:**` (two, de-gotcha'd, `·`-separated) `**failure_modes:**` (both
   directions) `**sources:**` `**provenance:** pending` `**framing_confidence:**`. Each paragraph on
   ONE line (the FTS parser reads `**field:** (.+)` per line). Refs/`[X-Yy]` tags live in the backing
   log, never in the entry prose.
5. **Mark `provenance: pending`** (mandatory for every new entry — the code defaults absent → verified).
6. **Log** the empirical backing in `verification-consensus-backing.md` (per-entry, with [refs] to
   original papers).
7. **Run the four-pass** via independent agents (academic-analyst ×3 + citation-verifier ×1), fresh
   context, adversarial. Record the run in the backing log. Fix unambiguous citation errors; route
   framing flags + everything else to Prayas.
8. **Re-verify parse:** `cd app && node -e "..."` buildIndex; confirm count + provenance split.
9. **Gate 4:** Prayas signs off (deletes the pending line). Only then `verified`.
